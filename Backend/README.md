# Race Simulator Backend

Spring Boot API and PostgreSQL persistence layer for the vehicle catalog and
deterministic race simulation engine.

## Requirements

- Java 21 or newer
- Maven 3.9 or newer
- Docker Desktop or another Docker Compose installation

## Start locally

From the repository root, build and install both Maven modules once:

```bash
mvn install -DskipTests
```

Then start PostgreSQL and the API:

```bash
cd Backend
docker compose up -d
mvn spring-boot:run
```

PostgreSQL runs on `localhost:5432` using the development-only credentials in
`compose.yaml`. Flyway creates the normalized vehicle catalog and seeds two
simulation-ready fixtures: a 2024 Ford Mustang GT Performance Package and a
2020 Chevrolet Corvette Stingray Z51.

## Vehicle catalog API

```text
GET /api/v1/vehicles/years
GET /api/v1/vehicles/makes?year=2024
GET /api/v1/vehicles/models?makeId=1&year=2024
GET /api/v1/vehicles/trims?modelId=1&year=2024
GET /api/v1/vehicles/popular
GET /api/v1/vehicles/{trimId}
```

IDs are generated by PostgreSQL. Discover them through the catalog endpoints
instead of hard-coding them in frontend code.

## Race simulation API

`POST /api/v1/races/simulate` accepts two trim IDs plus race conditions. A
quarter-mile standing-start request looks like this:

```bash
curl -X POST http://localhost:8080/api/v1/races/simulate \
  -H "Content-Type: application/json" \
  -d '{
    "vehicleAId": 1,
    "vehicleBId": 2,
    "race": {
      "goalType": "DISTANCE",
      "distanceMeters": 402.336,
      "startingSpeedMetersPerSecond": 0,
      "roadSurface": "PREPARED_DRAG_STRIP"
    }
  }'
```

The response includes the winner, margins, milestones, lead changes, and a
synchronized telemetry timeline for frontend animation. A request may instead
use `goalType: "SPEED"` with `targetSpeedMetersPerSecond`. Environment values
are optional; omitting them uses the engine's standard conditions.

Validation and application failures share a stable JSON error envelope. The
API also returns an `X-Correlation-Id` header that can be included in bug reports.

## Configuration

The defaults work with `compose.yaml`. Override these environment variables
when needed:

- `DATABASE_URL`
- `DATABASE_USERNAME`
- `DATABASE_PASSWORD`
- `SERVER_PORT`
- `CORS_ALLOWED_ORIGINS` (comma-separated; defaults to `http://localhost:5173`)

Do not commit production credentials.

## Tests

Run the complete reactor from the repository root:

```bash
mvn test
```

The backend service tests run without Docker. The end-to-end database test uses
Testcontainers and runs when Docker is available; otherwise it is skipped.
